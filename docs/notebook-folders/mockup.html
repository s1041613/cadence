Cadence · Notebook · 設計稿

便條加上資料夾

現在的 Notebook 是一條沒有盡頭的時間軸：所有便條依寫下的時間新到舊排列，只能往下捲找。 便條一多，「上週那個點子」就等於找不到。這份設計把參考畫面裡的分類方式搬進 Cadence—— 頁首下方一排資料夾分頁、最右邊的 ＋ 開新資料夾、 右下角的 ＋ 長出新增面板，在送出前就決定這則便條落在哪一格。

新增流程照著參考 app 的做法走：底部面板 ＋ 一列工具 ＋ 右下圓形送出鍵， 而且在內文裡打 # 就會即時跳出資料夾候選，不必先去點選單。 便條本身維持現在的樣子——一段純文字，沒有標題，所以面板只有一欄。 工具列上另一顆是日曆：便條可以放到某一天，寫的時候順手指定，事後也能長按選「移到某一天…」。 新增資料夾則刻意退回到最小的形式——一個置中跳窗、一格輸入框、取消 / 建立， 跟參考畫面的 Add Section 一樣，不做選色、選 emoji 那些會拖慢一次性動作的東西。

分頁列下方是常駐的搜尋列：分類解決「我知道它在哪一格」，查詢解決「我忘了放在哪一格」， 兩件事都得有，缺一個就得靠捲動硬找。至於既有的操作習慣一概不動—— 點便條內文就直接就地編輯，不多一顆編輯按鈕、也不另開頁面。

借的是結構，不是外觀：深色底、粉紅重點色留在參考 app，這裡維持 Cadence v2 的語彙—— #fafaf9 畫布、白色點紙卡片、JetBrains Mono，分頁藥丸沿用 Pv2Chip 的黑底 / 描邊兩態， FAB 沿用 Pv2Fab，面板沿用 Pv2DaySheet 的圓角與把手。

# 是同一個字

Cadence 的日曆 chip 本來就以 # 開頭。新增時在文字裡打 # 指定資料夾、工具列的資料夾藥丸、卡片上的標籤，用的是同一個符號，所以不必額外學。

新增資料夾＝跳窗

建資料夾是一次性的雜務，不值得一整張面板。置中跳窗、一格輸入框、取消 / 建立，名稱空白或重複時「建立」保持停用。

日期不搬走便條

放到某一天只是替便條加一個日期欄位：它仍舊留在 Notebook 的原資料夾，卡片多一顆日期 chip。分類回答「這是什麼」，日期回答「什麼時候要用」，兩件事互不取代。

查詢不看分頁

搜尋一律跨所有資料夾，結果卡片標出各自的資料夾。會用搜尋，多半正是因為不確定放在哪一格；先限縮在目前分頁只會讓人找不到。

永遠有地方可去

全部固定在最左邊、不能改名或刪除；沒指定資料夾的便條落在未分類。刪掉資料夾時便條不會跟著消失，一律退回未分類。

要動到的東西

這份設計是視覺提案，不是實作規格；下面只列出它必然牽動的既有檔案與行為，方便估工。

位置需要的改動
src/types/note.ts 多兩個欄位：folderId: string | null（null＝未分類）與 day: string | null（YYYY-MM-DD，null＝沒放到任何一天；存日不存時刻，便條沒有「幾點」這回事）。既有便條零遷移，也不必先建一個實體資料夾。「no title、no tags」那段刻意極簡的宣告維持不變，這份設計沒有動它。
新增 note_folders 使用者層級的資料夾：id、name、sortOrder。刪除時把該資料夾的便條 folderId 設回 null（不是連帶刪除）。
notebook-store.ts 沿用既有的樂觀寫入 ＋ 逐 id 佇列模式，新增 addFolder / renameFolder / removeFolder / moveNote；目前選中的分頁是本機 UI 狀態，不寫進 DB。
NotebookViewV2.vue feed 依選中的資料夾過濾（全部 不過濾）；排序邏輯不變，仍嚴格以 createdAt 新到舊。
Pv2NoteComposer.vue 速記藥丸退場，改為 Pv2Fab ＋ 底部面板：一欄內文、資料夾藥丸、日期藥丸、圓形送出鍵，外加 # 的即時候選。
搜尋（新元件） 常駐搜尋列 ＋ 前端純本機比對：便條全數已在 store 裡，body 做不分大小寫的子字串比對即可，不必打 API。有查詢字串時忽略選中的分頁、收起 FAB。
Pv2NoteCard.vue 就地編輯的行為原封不動（點內文＝進入編輯、失焦或 Esc 送出）。右上角的垃圾桶收進長按選單，選單多出「移動到…」與「移到某一天…」；有日期時多顯示一顆日期 chip；在「全部」與搜尋結果裡多顯示一顆資料夾標籤。
選日期面板 沿用 Pv2MonthSheet 的月格與底部面板外殼，加上今天 / 明天快捷與「清除日期」。setNoteDay 與其他寫入共用同一套樂觀更新。
缺一個跳窗元件 repo 目前只有底部面板（Pv2DaySheet / Pv2MonthSheet）與 CdPopover，沒有置中的 alert 式跳窗。新增資料夾、改名、刪除確認都要用它，值得做成共用元件。

還沒決定的

  • 放到某一天的便條，要不要在 Day 視圖（MY DAY）也看得到？看得到才算真的「移過去」，但那等於把 Notebook 的內容帶進日曆，得先想清楚它跟 task 的差別。
  • Notebook 要不要能只看「有日期的便條」？例如分頁列最前面多一顆「排程」，或搜尋列旁一顆篩選。
  • 搜尋要不要記住最近查過的字？空查詢時列出最近幾筆很方便，但也等於把使用者找過什麼留在畫面上。
  • 資料夾要不要有數量上限？分頁列一屏約放得下四到五個，十個以上就只能靠橫捲找。
  • 「全部」要不要記住上次選的分頁？記住對長期待在單一資料夾的人比較順，但每次回來看到的畫面就不一定相同。
  • 便條要不要能同時屬於多個資料夾？現在是一則一格——若要多對多，分頁列的語意就得從「資料夾」改成「標籤」，# 的寫法倒是已經預留了這條路。
