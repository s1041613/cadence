    ⚠️ 與參考圖唯一的刻意差異

    參考圖底部是「選一個子任務開始專注」（灰色 disabled）。那是舊模型 —— 選子任務才能開始。

    你已定案的模型是番茄開在父任務上，子任務只是檢查清單。所以底部維持現況的 Start focus session，永遠可按、不需選取。子任務列因此也不需要選取態。

    摺疊：整個標題列都是開關

    不做小箭頭按鈕 —— 100px 寬的標籤是大得多的點擊目標，而且 hover 時整列都有回饋，不用瞄準。箭頭只是狀態指示，用旋轉而非換符號，讓它讀起來是同一個東西的兩種狀態。

    預設狀態有子任務→展開，沒有→收合。空清單展開只是露出一行灰字和 composer，佔 88px 卻沒資訊
    收合時保留計數 1/3 —— 這是收合狀態下唯一的資訊，拿掉那列就只剩標籤
    composer跟著收合。它是清單的一部分，不是獨立入口
    刪到剩 0 個維持展開，不自動收合 —— 在使用者沒動作時改變版面會讓人失去方位

    為什麼放在 POMODOROS 和 NOTES 之間

    卡片的列由穩定度排序：REMINDER 與 POMODOROS 是單值設定，NOTES 是自由文字。子任務是會增長的清單，介於兩者之間。

    放在 NOTES 之上還有一個實際理由：NOTES 是唯一高度不定的列，若子任務排在它下面，新增一筆會把整張卡的底部往下推，按鈕位置就不穩定。

    沿用現有的三欄格線

    標題列SUBTASKS 用 mono 標籤，右側計數 1/3 對齊 3/3 那個 meta 欄
    子任務列22px checkbox 取代 100px 標籤溝 —— 清單需要比設定列更緊湊，44px 而非 48px
    分隔線同樣 1px solid #e2e2e2，讓子任務讀起來是卡的一部分

    composer 是一列，不是按鈕

    虛線 + 加上永遠可見的輸入框，讓「新增」看起來就是下一列，不是要先點開的東西。輸入有字時虛線轉實線、右側浮出 ENTER 提示。

    送出後不關閉、不失焦 —— 連續打三個子任務是最常見的路徑。

    清單捲動，卡片不長高

    max-height:196px（約 4.5 列）自捲。這同時解掉 EventPreviewPopoverV2.vue:2 的 :approx-height="520" 問題 —— 卡片高度有上限，定位就不會翻轉。

    但 approx-height 仍應隨子任務數估算（0 個和 5 個差約 190px），否則靠近螢幕底部的事件會定位不準。

    刪除：hover 才出現

    子任務沒有 edit 卡，刪除必須在這裡。× 平常隱形，hover 或鍵盤 focus 才顯示 —— 清單靜止時保持乾淨。

    觸控裝置沒有 hover，需要改成左滑刪除或長按，這一項要另外決定。

    編輯：點標題就地改

    標題本身是按鈕，點下去變成輸入框（試試看點左邊的子任務名稱）。Enter 或失焦存檔，Esc 取消還原。

    空白標題拒絕存檔、還原原文 —— 標題是唯一能辨識子任務的東西，空的那列就認不出來了
    其他地方不提供編輯 —— 專注畫面唯讀，結算 sheet 只能勾

    打勾＝定案，標題就鎖住

    勾選後標題變灰加刪節線，點不動。這讓刪節線是誠實的訊號而不是裝飾 —— 畫了線的字就是不能改的字。

    checkbox 永遠可按。再點一次取消勾選，標題就恢復正常顏色、可以編輯。所以勾錯了不會卡死：取消 → 修改 → 重新勾。

    這是唯一的回頭路，刻意如此 —— 已經定案的項目要用一個明確動作才能解開，不該被默默改掉。

    勾選＝純 done 布林

    不觸發任何番茄邏輯，走 toggleDone 同一條樂觀寫入路徑。完成的子任務留在原位不重排 —— 清單短，重排的位移成本高於好處。
