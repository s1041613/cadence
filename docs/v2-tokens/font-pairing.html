Instrument Serif 搭配比較

標題固定 Instrument Serif，只換「數字和小字」那一層
先講判斷標準。標題字體已經定了（Instrument Serif），所以問題只剩「搭配的無襯線/等寬字體選哪個」。 判斷這件事有三個軸，而且它們會互相拉扯：

1. 對比 — 搭配字體要跟襯線標題有足夠差異，才不會糊成一團，但也不能打架。
2. 中文字形 — 你的介面是繁體中文。事件標題會有大量中文。
3. 字重完整度 — 設計會用到幾階字重。

五種組合並排

同一個版型、同一組 v1 顏色。事件標題刻意放了中英混排，因為那是最容易露出破綻的地方。

中文字形對照

這是選擇的關鍵。三個字體渲染同一段中文，注意字形差異和字重支援。

Zen Kaku 是日文字體，不是繁中字體。它有漢字，但字形依日文標準設計。 部分字的筆畫和繁體中文寫法不同（日文漢字經過簡化，例如「直」「每」「骨」「角」這類字）。 一般使用者不一定會注意到，但如果你在意繁中字形的正確性，這是實質差異。

JetBrains Mono 完全沒有中文，遇到中文會 fallback 到系統字體（macOS 上是蘋方）。所以「全部用 Mono」實際上是「英數用 Mono、中文用系統字體」的混排。

字重支援

字體可用字重600 有嗎中文已在專案
Instrument Serif400（僅一階）否無是
JetBrains Mono100–800是無是
Zen Kaku Gothic New300 / 400 / 500 / 700 / 900否日文字形是
Inter100–900是無是
Noto Sans TC100–900是繁中字形是（但沒 token 指向它）
我的建議：第五種（Mono 數字 + Noto Sans TC 事件文字）。

理由是它讓每個字體做它最擅長的事：數字和標籤用 Mono（等寬對齊、跟襯線標題有對比、技術感是刻意的主張）， 事件標題用 Noto Sans TC（繁中字形正確、字重完整、中英混排時字體一致）。

純 Zen Kaku 的問題不是「不配」，是它兩邊都不夠好 —— 對比不如 Mono 明確，中文字形不如 Noto 正確，而且沒有 600 字重。
但這裡跟你先前的決定有衝突，要你確認。 你說「不管哪一組 token 都只能用圖片中的字體」，而 Noto Sans TC 不在那張圖裡。 不過它已經安裝在專案裡（@fontsource/noto-sans-tc，且 app.css 已 import 400/500/700），只是目前沒有任何 token 指向它。 所以用它不會新增依賴，但確實超出「圖片中的字體」這個範圍。
